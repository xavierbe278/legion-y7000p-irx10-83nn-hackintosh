# 踩坑记录（按时间顺序）

这份文档记录从「装不上」到「日常可用」的全过程，方便后来者少走弯路。

## 阶段一：装不上系统

| # | 现象 | 排查 | 结论 |
|---|---|---|---|
| 1 | 安装器崩溃 `Non-monotonic time` | 换 EFI、换 U 盘、换 USB 口均无效 | TSC 不同步 → `TscSyncTimeout=500000` + `CpuTscSync.kext` |
| 2 | 改 boot-args 后行为没变化 | `nvram -p` 里还是旧值 | `NVRAM > Delete` 必须包含 `boot-args` |
| 3 | `OC: Halting on critical error` | 回退 config | `ScanPolicy` 写成 `0x40100` 非法，只能 `0` |
| 4 | F12 没有 OpenCore 项 | bless 不生效 | 用 OC 的 `bootx64.efi` 覆盖 `EFI/Microsoft/Boot/bootmgfw.efi` |
| 5 | `installer -pkg` 报 ENOSPC | df 显示空间充足 | 安装器脚本误判，改用 `createinstallmedia` 后的手动流程 |

## 阶段二：能进系统但没加速

| # | 现象 | 结论 |
|---|---|---|
| 6 | 只有帧缓冲、无 Metal | `IONDRVSupport` 必须 `Kernel > Block`（Exclude） |
| 7 | HDMI 闪一下黑一下 | 去掉 `nvfbhotplugpoll` |
| 8 | 亮度不能调 | `nvrmacpibl=1` |
| 9 | 打开「显示器」设置极卡 | 驱动枚举大量 DSR 模式，用 `displayplacer` 代替 |

## 阶段三：网卡蓝牙

| # | 现象 | 结论 |
|---|---|---|
| 10 | Wi-Fi 完全不出现 | 通用 EFI 的 `SSDT-Disable_Network_RP05` 把根端口藏了，必须关闭 |
| 11 | 蓝牙开关一直"正在打开" | 缺 `-btlfxboardid`；缺 NVRAM 两键；且 `Add`/`Delete` 都要有 |
| 12 | 蓝牙能开但连不上设备 | `BlueToolFixup` 必须用补丁版（原版不认本机 board-id） |

## 阶段四：触控板（最曲折）

| # | 现象 | 结论 |
|---|---|---|
| 13 | 触控板完全无反应 | 官方 VoodooI2C 只匹配 `7A4C~7A4F`，本机是 `7A7C` |
| 14 | 扩大匹配后能用了 | 但 GPIO 拿不到中断 → 需要认 `INTC1085` 的 VoodooGPIO 1.1.5 |
| 15 | 能用了但点击时指针被拽一下 | PS/2 触控板同时在汇报 → 关 `VoodooPS2Trackpad` / `VoodooPS2Mouse` |
| 16 | 轮询模式抖动 | 改回 GPIO 中断模式 |
| 17 | 关机/重启卡死 | 一度以为是 VoodooI2C 的 `stop()`，做了 20 多轮实验（版本、补丁、SSDT、USB 映射）——**全都不是主因** |

## 阶段五：真凶

| # | 现象 | 结论 |
|---|---|---|
| 18 | 只有插着 2.4G 鼠标接收器才卡 | 拔掉就一切正常 |
| 19 | `ioreg` 发现该设备 `HIDRMDeviceState = "Unknown"` | DriverKit HID 初始化失败 |
| 20 | boot-args 加 `dk=0x0` | **一次性解决**：触控板+鼠标同用、热插拔、菜单重启全正常 |

👉 详见 [USB 外设项目](https://github.com/xavierbe278/legion-y7000p-irx10-usb-receiver-freeze)

## 经验总结

1. **"外设引起的系统级卡死"优先怀疑设备，不要先怀疑驱动栈。**
2. 判断捷径：*拔掉某个设备就好了* → 一定先做 ABA 测试（插/拔对比），再动配置。
3. OC 的 `Kernel > Patch` 对**注入的 kext**经常不生效（且 schema 校验失败会被静默丢弃，日志里只有 `OCS: No schema for ...`）→ 要改二进制就直接改文件。
4. 每次改配置都要**留备份**，并且知道怎么在 Windows 侧恢复 EFI。
## 阶段六：双系统时间对不上

| # | 现象 | 结论 |
|---|---|---|
| 21 | 每次从 macOS 切回 Windows，时间差整整 8 小时 | macOS 把硬件时钟（RTC）当 **UTC** 存，Windows 默认当**本地时间**存 |

**解决**：让 Windows 也按 UTC 读硬件时钟

```powershell
# 管理员 PowerShell
reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_DWORD /d 1 /f
powercfg /h off          # 关闭休眠/快速启动，否则该设置可能不生效
w32tm /resync /force     # 校时（可能需要重启一次才完全生效）
```

脚本见 `scripts/fix-windows-time.ps1`。

**注意**：设置完成后的第一次可能看到时间**跳了 8 小时**（因为硬件时钟里还存着本地时间，而 Windows 现在按 UTC 解读）。此时手动把系统时间改回正确的本地时间，重启一次，Windows 会以 UTC 写回硬件时钟，之后两边就一致了。
